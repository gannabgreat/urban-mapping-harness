# Urban Mapping Harness — 시스템 명세 (정본)

> 이 문서가 정본이다. 스킬·에이전트·커맨드·템플릿은 모두 이 명세를 따른다. 충돌하면 이 문서가 이긴다.

## 1. 정체성
도시설계 수업·공모의 **현황분석(Site Analysis / Urban Mapping)** 단계를 AI 에이전트 팀이 수행하기 위한 하네스. 결과물은 **A3 분석 시트 묶음**(PNG 보기용·PDF 벡터·SVG 편집용)과 그 뒤의 데이터·코드·출처 기록이다.

## 2. 불변 원칙
1. **데이터 → 코드 → 시트.** 시트는 손으로 그리지 않고 스크립트로 그린다. 다시 돌리면 같은 시트가 나와야 한다.
2. **문장 속 숫자 = 계산값.** 「골목 식음 업소 62%」 같은 숫자는 데이터에서 계산해 문장에 꽂는다. 손으로 쓴 숫자 금지.
3. **fail-closed.** 못 읽은 값은 「없음/0」이 아니라 `판독 불가` 또는 `현장 확인`. 빈 결과는 실패로 올린다.
4. **출처·기준일 명기.** 레이어마다 출처와 기준일(예: 수치지형도 2025, 건축물정보 2026, 로드뷰 2026-07)을 `SOURCES.md` 와 시트 각주에 남긴다.
5. **추정은 추정이라고 쓴다.** 항공사진 판독 치수(±0.3~1 m), 가정 층고, 사진으로 고른 건물 번호는 「추정·현장 확인」 표시.
6. **만든 쪽과 검토하는 쪽을 분리.** 4차 적대적 검토(§5)를 통과해야 제출본.
7. **자동 판정은 표본 확인 후.** 색 분류·사진 판독 규칙은 표본을 직접 보고 맞는지 확인한 뒤 전체 적용. (실패 사례: 위성사진 초록 판정이 지붕까지 90% 초록 → 폐기·재작성)
8. **피드백은 롤백 가능하게.** 시트·데이터는 git 으로 버전 관리. 사람이 「롤백」하면 커밋 단위로 되돌린다.
9. **결론은 한 문서로 귀결.** 시트 결론은 `CONCLUSION.md` 하나로 모이고, 거기와 모순되면 안 된다. 결론 한 줄마다 근거 시트 번호와 데이터 파일을 단다.
10. **사람 판단은 🔲 미결정.** 넣고 뺄 것·해석이 갈리는 것은 지어내지 말고 `CONCLUSION.md` 「🔲 미결정」에 적고 묻는다. 현장에서 잴 것은 `FIELD_TODO.md` 로(둘을 섞지 않는다).

## 3. 프로젝트 구조 (인스턴스 1개 = 디렉터리 1개)
```
CLAUDE.md            인스턴스 결정 항목(대상지·담당 가로·규격·축척·제출일·심사자 페르소나·교수 피드백)
CONCLUSION.md        시트 결론이 귀결되는 문서(핵심 이슈·SWOT·다음 범위·🔲 미결정)
SOURCES.md           레이어별 출처·기준일·라이선스
FIELD_TODO.md        현장에서만 확인 가능한 항목
sheets/SHEETS.md     시트 목록·상태(초안/검토n차/제출)
data/raw/            교수 PDF·다운로드 원본(수정 금지)
data/                가공 데이터(json·csv·geojson)
scripts/             수집·정합·판독·작도 스크립트(run.sh 전체 재실행, sheet_template.py 축척 검사 포함 견본)
photos/              답사사진(번호·방향 정렬)
out/                 시트 PNG·PDF·SVG, 묶음 PDF
_state/              sheet-status.json · review-log.json
```

## 4. 단계
1. **자료 수집** — 교수 제공 PDF(현황도·가로규모·베이스)에서 벡터 추출, 공공데이터·지도 수집.
2. **좌표 정합** — 교수 도면 좌표를 실제 좌표계(EPSG:5186 등)에 맞춘다. 잔차를 숫자로 남긴다.
3. **시트 초안** — 기본 분석(FGP·용도·노후도·층수·가로위계·교통) → 가로 세부(층별용도·입면·평면·단면·행태) → 오픈스페이스 → 자유주제 → 종합(SWOT) → 다음 프로젝트 범위.
4. **보강** — 실제 축척(지도 1:2,500, 평단면 1:200~1:250), 치수 판독, 누락 항목.
5. **검토 4차** (§5)
6. **피드백 반영** — 수업 피드백을 `CLAUDE.md` 피드백 절에 원문 그대로 적고, 시트 번호·내용을 바꾼다.
7. **현장 확인** — `FIELD_TODO.md` 를 들고 나가서 채운 값으로 추정치를 교체.

## 5. 적대적 검토 4차
| 차수 | 검수자 | 보는 것 |
|---|---|---|
| 1차 | verify (검수 전용 에이전트) | 시트 PNG ↔ 데이터 대조: 축척 표기, 숫자, 범례, 중복 집계 |
| 2차 | verify (새 호출) | 1차 수정본 + 단면 높이·치수·문장 사실 |
| 3차 | blind-critic (이전 맥락 0) | 교안 항목 누락, 논리 비약, 「이 숫자 근거는?」 |
| 4차 | 다른 세션·다른 봇 독립 검토 | 판정 기준 일관성(같은 개념을 시트마다 다르게 세지 않았나) |
- 지적은 **그대로 반영하지 않는다.** 데이터로 재계산해서 맞는 것만 고치고, 틀린 지적은 이유와 함께 기각해 `_state/review-log.json` 에 남긴다.
- 차수마다 고친 것·기각한 것 건수를 기록한다.
- 검수 에이전트(verify·blind-critic)는 읽기·계산 도구만 쓴다. 기록(`review-log.json`)은 본체가 한다.
- 3차 blind-critic 은 인스턴스 `CLAUDE.md` 의 심사자 페르소나로 본다.

## 5-1. 강제 장치 (hooks/)
문장 규칙 중 둘은 PreToolUse 훅(`hooks/gate.py`)이 실제로 막는다.
- `data/raw/` 원본을 Write/Edit 로 고치려 하면 차단.
- `_state/sheet-status.json` 에서 시트를 「제출」로 올릴 때 `review-log.json` 에 1·2·3·4차 기록이 다 없으면 차단. review-log 를 못 읽으면 차단(fail-closed).
- Bash 로 쓰는 경로는 못 막는다. 실수 방지용이지 보안 장치가 아니다.

## 6. 사람 / 자동 분담
- **사람**: 답사·야간 사진, 층별 업소 조사, 피드백 전달, 넣고 뺄 판단, 결과 확인·롤백, 정면 사진, 손 편집(Canva·일러스트).
- **자동**: 벡터 추출·정합, API 수집, 로드뷰·항공사진 판독, 작도, 숫자 계산, 검토, 버전 관리.
- AI 는 사람 몫을 대신 지어내지 않는다(답사 안 한 곳의 「현장 관찰」 금지).

## 7. 산출 규격 (기본값 — /um-init 에서 바꾼다)
A3 가로, 지도부 S 1:2,500(인쇄 100%), 평단면 S 1:200, 시트마다 PNG 170dpi·PDF·SVG, 묶음 PDF 1개.
